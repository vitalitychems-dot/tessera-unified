Vitality Supply website audit

September 14, 2026 · GitHub import and initial repair pass

Status: The original website runs in Replit preview. It has not been published. This is not a certification that every defect has been eliminated or that the business meets regulatory requirements. Paid checkout and accounts require service configuration before a full store launch.

Product imagery

Thirty inspected compound-and-strength mappings now use matching vial images, including Retatrutide 20mg. Image selection no longer falls back to unrelated compounds or strengths. Product cards, variant detail views, search, cart, SARM and research-set views use the same strict policy.

Other variants—including currently unverified non-vial, SARM and set photos—display a labeled “Photo unavailable” image. Complete photographic coverage remains outstanding. Verified original photos are required; labels have not been fabricated or altered to imitate real stock.

Entrance and navigation

  • 18+ entrance confirmation and under-18 decline action.
  • Keyboard focus handling, background interaction blocking and scroll-lock release synchronized with acceptance.
  • Acceptance remains usable when browser storage is blocked.
  • Category/search updates use non-blocking React transitions.
  • Removed expensive sticky background blur and made the mobile welcome popup scrollable.

These are implementation improvements, not measured promises of lag-free performance on every device.

SEO repairs

  • Unique page metadata and social previews; private account, admin and checkout pages marked noindex.
  • Canonical URLs use a single configurable site URL, retaining the original vitalitysupply.org domain until a new canonical domain is confirmed.
  • Generated sitemap covers 94 public URLs, including 84 catalog products.
  • Removed obsolete hosting-platform manifest links and updated structured data.

After publishing, confirm the canonical domain, sitemap reachability, indexing and real-device performance. Search ranking improvements have not been measured.

Critical commerce findings

  • The imported checkout collected card-like details without an actual payment integration and could report order success after an error. Replaced it with an explicit unavailable state that preserves the cart.
  • Disabled unsafe order and credit mutations pending a server-validated payment/order implementation.
  • Removed unauthenticated staff-account auto-provisioning and an embedded credential. Treat the old credential as compromised and rotate it anywhere it was reused; removal here does not erase GitHub history.
  • Removed shared development identity fallback. Unconfigured accounts now fail explicitly.
  • Production no longer silently uses an in-memory customer database.

Verification performed

  • TypeScript checks passed.
  • Production build passed during the import repair.
  • Managed preview server starts successfully.
  • Mobile and desktop entrance screenshots were inspected. The final desktop capture showed no browser errors.

Full end-to-end checkout, live payment, account, production SEO, security scanning and performance benchmarking are not completed. No payment was taken and no production customer data was migrated.
